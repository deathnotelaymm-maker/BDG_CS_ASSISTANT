# v1.15.2 — AI Response Reliability Repair

## Scope

This release repairs customer-facing AI reliability without weakening tenant
isolation, platform-context enforcement, grounded-source rules, connector SSRF
protection, rich-content sanitization, or the v1.15.1 release pipeline.

## Root-cause findings

The supplied Render logs show successful `POST /chat` requests with HTTP 200 and
roughly 5–13 second durations. The red card was therefore not proof of a failed
browser-to-Render connection. It was a structured `error` block generated by
the backend after an internal judge/composer failure or no-match decision.

The audit also found:

- two sequential provider calls multiplied the chance of turn failure;
- live calls ignored the saved retry and timeout policy;
- the judge prompt could become excessively large;
- locale matching did not fall back from Indonesian to the platform's verified
  default-language source content;
- legacy stored copy incorrectly told customers to check their internet;
- public output exposed raw provider error text;
- the Quality Center allowed empty-expectation degraded runs to pass.

## Backend repairs

- Added `src/chat-reliability.js` with deterministic multilingual social intent,
  respectful abuse boundaries, localized safe fallbacks, system UI copy, and a
  narrow non-executable JSON trailing-comma repair.
- Wired `max_retries` and `provider_timeout_ms` into judge and composer calls.
- Added retry handling for network errors, timeouts, HTTP 429, and HTTP 5xx with
  bounded backoff and a 20-second provider deadline for the whole turn.
- Added a 40-item / 52,000-character judge catalog budget.
- Added the `exact_then_default` locale strategy. Exact and base-language
  content remains preferred; only the current platform's default locale is the
  final fallback.
- Honored source order when constructing the model catalog instead of appending
  source types in a hard-coded order.
- Skipped the composer for local conversation, greeting, clarification, and
  no-match turns.
- Added direct approved-source fallback when the composer fails after a valid
  match.
- Changed degraded responses from `error` blocks to neutral `notice` blocks and
  optional configured handoff buttons.
- Removed raw `provider_error` from public responses.
- Added structured `ai_chat_completed` logs with status, resolution path,
  provider attempts, catalog size/budget, selected source type/locale, and
  latency. Customer message text and secrets are not written to that event.
- Persisted `response_status`, `resolution_path`, `degraded_reason`, and
  `provider_attempts` in Chat Logs.

## Chat and Admin repairs

- Added safe English, Indonesian, Hindi, Chinese, and Burmese UI/fallback copy.
- Chat converts a legacy API `error` fallback into an informational notice
  during rolling deployments.
- Dynamic Chat content now localizes online, welcome, placeholder, and busy
  strings instead of duplicating the default-language text for every locale.
- Admin Source Router now offers and defaults to “Exact/base, then platform
  default.” Strict policies remain selectable.
- Quality tests now fail a degraded live-router result.

## Migration 034

- changes the new source-router default to `exact_then_default`;
- upgrades existing `exact_then_base` rows to the repaired default;
- removes known legacy network-blaming provider-error copy;

The file is immutable after production application and is protected by the
existing SHA-256 migration registry.

## Tests

- Added a focused AI reliability regression suite.
- Expanded the PostgreSQL/API integration suite with a deterministic DeepSeek
  HTTP fake for successful grounded answers and retryable composer outage.
- Integration coverage now asserts Indonesian local conversation, default-locale
  source fallback, verified-source composer fallback, retry persistence, no red
  error blocks, and no public provider detail leakage.
- The production workflow runs the new reliability suite before deployment.

## Dependency note

All four npm trees report zero known vulnerabilities. npm still prints
deprecation notices from ExcelJS 4.4.0's internal archive/import packages. Those
are transitive warnings, not current audit findings; forced major overrides were
not added because they would risk corrupting workbook import/export behavior.
